# w12f 实现脉络（FA3 骨架：TMA + wgmma + mbarrier）

> 代码：`kernels/w12f_fa2_tma.cu`（438 行）+ `kernels/w12f_fa2_tma.py`
> 它是什么：**FlashAttention-2 的前向，QK 用 wgmma、K/V 用 TMA 搬运、mbarrier 双缓冲。**
> 它不是什么：没有 warp specialization、没有 FP8、PV 仍是 mma.sync。

---

## 一、这个 kernel 一次调用算多少活

```
grid  = (ceil(S / TILE_M), B * H)      // 每个 block 负责「一个 Q 块 × 一个 head」
block = 256 线程 = 8 warp = 2 个 warpgroup
```

一个 block 内部要做的事：

```
for 每个 K/V tile（jt = 0 .. jt_end）
    S = Q(128×64) · K(32×64)ᵀ        → 128×32 的分数
    P = softmax(S) 的 online 版本     → 128×32
    O += P(128×32) · V(32×64)        → 128×64 累加
最后 O 除以 l 写回 global
```

关键：**Q 只在开始时进 smem 一次，O 只在最后写一次，S/P 全程在寄存器。**

## 三、线程划分（8 warp 怎么分工）

```
warp_id = tid / 32      → 0..7
wg      = warp_id / 4   → 0 或 1        （第几个 warpgroup，各管 64 行 Q）
wi      = warp_id % 4   → 0..3          （warpgroup 内第几个 warp，各管 16 行）

row0 = wg*64 + wi*16 + lane/4      （tile 内行号，0..127）
row1 = row0 + 8                    （同一条 lane 负责两行，隔 8）
```

**为什么 4 条 lane 一组管一行**：wgmma/mma.sync 的 C 布局规定
`C[m][n]` 里 `m = lane/4`、`n = 2*(lane%4) + {0,1}`，这条 lane 拿两列。加上 `+8` 跳后半块，
一条 lane 一共 4 个 float —— 对应 `sc[TILE_N/8][4]` 里的那 4 个。

于是 `TILE_N=32` → 4 个 n-tile（每 8 列一个），`sc[4][4]` = 16 个 float/线程/warpgroup。

## 四、一次 `jt` 迭代的 7 步（照着源码看）

```
① 发射下一块          if (jt+1 <= jt_end) load_kv(jt+1, buf^1)
② 等当前块            mbar_wait(&vbar[buf], (jt >> 1) & 1)
                      __syncthreads()
③ S = Q·Kᵀ            4 × wgmma.m64n32k16（kk=0..3），wgmma_commit()/wait0()
④ mask + 行 max       块内 j>row 或 j>=S → -inf；warp_max4 合并 4 条 lane
⑤ 重缩放 + exp        acc *= alpha；p = exp(sc - m_new)；行和 l
⑥ P 打包              sc → pA[2][4]（pack2，零 smem）
⑦ O += P·V            2 ks × 8 nd = 16 条 mma.sync，V 由 ldmatrix.x2.trans 读
```

**屏障只出现在 ②**：因为整个迭代里唯一跨线程共享的是 smem 里的 K/V tile。
第 ③ 步之后全是寄存器操作，不需要任何 `__syncthreads()`。

### ② 里 mbarrier 的时序

- 每条 buffer 一条 mbarrier（`vbar[0]`、`vbar[1]`），`mbar_init(&vbar[i], 1)` —— count=1，因为只有 tid 0 去 arrive。
- tid 0 一次 `arrive_expect_tx(8192)` 声明「会有 8 KB 到」，然后发**两条** TMA（K 4 KB + V 4 KB），两条都挂在同一个 barrier 上。
- phase 推导：buffer 每 2 轮复用一次 → `phase = (jt >> 1) & 1`，第一次是 0。
- **`mbar_wait` 必须在 `if (jt <= jt_end_wg)` 外面**：warpgroup 1 可能跳过计算，但绝不能跳过等待，否则 barrier 永远等不到。

## 五、三处布局为什么不一样（最容易混的地方）

| 数据 | 谁写进 smem | 谁读走 | 布局 | 描述符 |
|---|---|---|---|---|
| Q | 线程手工写（`:214`） | wgmma（A） | core-matrix | `swizzle=0`，LBO 128 / SBO 1024，偏移 `kk*128` |
| K | TMA | wgmma（B） | 128 B swizzle | `swizzle=1`，LBO 1（不用）/ SBO 1024，偏移 `kk*16` |
| V | TMA | **ldmatrix**（PV 是 mma.sync） | 128 B swizzle | `swz()` 手算地址 |

三条判据：

1. **wgmma 的 A、B 描述符各自独立**，一个 core-matrix 一个 swizzle 是合法的。
2. **TMA 只能产出「线性」或「swizzled」**，产不出 core-matrix。所以 K 一旦交给 TMA，就必须用 `swizzle=1` 的描述符。
3. **V 不经过 wgmma**：PV 用 `mma.sync`，因为 P 在寄存器里，而 wgmma 的 SS 形式要求 A 来自 smem。

## 六、为什么 PV 还是 mma.sync（以及它的代价）

```
mma.sync 要求 A、B 都在寄存器里
  → V 必须由 ldmatrix 从 smem 拉到寄存器
  → 每个 warp 都需要整块 V（它的 16 行 P 要乘全部 32 个 key）
  → 8 个 warp × 4 KB = 每轮从 smem 读 32 KB，而 tile 只有 4 KB（8 倍放大）
```

下一步 w12g：把 PV 换成 wgmma 的 **RS 形式**（A 从寄存器、B 从 smem），放大消失。

## 七、现在的机器级证据（本地就能验）

```
125 → 101 registers（省掉 cp.async 的地址计算和 cm()）
0 spill，32784 B smem（16384 + 4096×2 + 4096×2 + 16）

UTMALDG.3D            4    ← K、V 各两条（prologue + 循环各内联一次）
HGMMA.64x32x16.F32    4    ← wgmma 没退化
LDSM.16.MT88.2       16    ← 只剩 PV 读 V
HMMA.16816           16    ← PV
LDGSTS.E.BYPASS       0    ← cp.async 全部消失
SYNCS.ARRIVE.TRANS64  2    ← expect_tx
SYNCS.EXCH.64         2    ← mbarrier.init
SYNCS.PHASECHK.TRYWAIT 2   ← try_wait
WARPGROUP.ARRIVE/DEPBAR 4/4 ← wgmma 的提交与等待
```

**`LDGSTS = 0` + `UTMALDG = 4` 就是「K 也走 TMA 了」的机器级证据。**

## 九、上机验证顺序（Hopper，compute_cap 必须 9.0）

```bash
nvidia-smi --query-gpu=name,compute_cap
python kernels/wgmma_warmup.py          # 先验描述符语义
python kernels/w12e_fa2_wgmma.py        # QK=wgmma，K/V=cp.async
python kernels/w12f_fa2_tma.py          # 本文件
```

判据：三档 `max|diff|` 必须与 w12e 位级相同（3.644e-04 / 4.944e-04 / 5.429e-04）。

### 唯一没把握的地方

`b_lbo=1 / b_sbo=1024 / swizzle=1 / 偏移 kk*16` 这套 B 描述符参数是按 PTX 语义推的，**没在 Hopper 上验过**。

- 若 w12e PASS、w12f 的 diff 全错（不崩、不是 nan）→ 九成是 B 描述符。
- 调试顺序：① 看 `S[0,0,0,:8]` 是错位还是全错 ② `b_sbo` 试 512 / 2048 ③ 偏移试 `kk*32`。
- 若崩或卡死 → 是 mbarrier（`expect_tx` 字节数、phase），与描述符无关。
