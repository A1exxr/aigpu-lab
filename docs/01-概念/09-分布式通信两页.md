# 分布式通信两页：ring allreduce 与 TP/PP 的通信代价

> 定位：**不是"我做过分布式"的证据，是"我知道单卡到墙之后会发生什么"的补丁。**
> 你没有任何集群实践，所以这份文档的目标只有一个：面试问到时能画出图、算出数、说清边界。
> 全文约 15 分钟读完；能背下来的只有三样：**ring 的 2(N−1)/N、TP 每层两次 allreduce、PP 的 bubble 公式**。

---

## 0. 先统一术语

| 词 | 含义 |
|---|---|
| rank | 一个进程/一张卡 |
| world size (N) | 总卡数 |
| allreduce | 所有卡各有一份数据，归约（求和）后**每张卡都拿到完整结果** |
| reduce-scatter | 归约后每张卡只留 1/N 份 |
| all-gather | 每张卡把别人的 1/N 份收齐，拼成完整结果 |
| S | 每张卡上要归约的数据量（字节） |
| B | 单条链路的单向带宽（IB 400 Gb/s = 50 GB/s） |
| α | 一次通信的固定延迟（IB 上约 1–2 µs） |

**关键认知：allreduce = reduce-scatter + all-gather。** ring 算法就是把这个恒等式拆成两半各做一轮，从而避免任何一张卡成为瓶颈。

---

## 1. ring allreduce：为什么它是最优的

### 1.1 两阶段，各 N−1 步

N 张卡排成一个环，数据切成 N 块：

```
阶段一 reduce-scatter（N−1 步）：
  第 k 步：rank i 把它手里第 (i−k) mod N 块发给 rank i+1，同时收 rank i−1 的块，累加
  走完 N−1 步后：每张卡手里有一块「已经完全归约」的块

阶段二 all-gather（N−1 步）：
  同样的环形传递，但只转发、不累加
  走完 N−1 步后：每张卡手里都是完整结果
```

### 1.2 通信量（这就是要背的那个数）

每一步每张卡**发送 S/N 字节、接收 S/N 字节**，共 2(N−1) 步：

$$\text{每卡发送量} = (N-1)\cdot\frac{S}{N} \times 2 = \frac{2(N-1)}{N}\cdot S$$

| N | 每卡发送 | 相对 S |
|---|---|---|
| 2 | 1.0 S | 1× |
| 4 | 1.5 S | 1.5× |
| 8 | **1.75 S** | 1.75× |
| 64 | 1.97 S | ≈2× |
| ∞ | 2 S | 下界 |

**下界为什么是 2S**：每个字节必须被"读一次、写一次"，所以任何 allreduce 至少要搬 2S。ring 在 N→∞ 时逼近这个下界，所以叫**带宽最优**。

### 1.3 和朴素实现差多少

朴素做法（rank0 收集 N−1 份 → 求和 → 广播回去）：

$$\text{rank 0 的发送量} = 2(N-1)\cdot S$$

**N = 8 时是 14 S，比 ring 的 1.75 S 差 8 倍。** 而且瓶颈卡一慢，全员等它——所以没人这么写。

### 1.4 时间模型（面试可以直接套）

$$T \approx \underbrace{\frac{2(N-1)}{N}\cdot\frac{S}{B}}_{\text{带宽项}} + \underbrace{2(N-1)\cdot\alpha}_{\text{延迟项}}$$

**举例（记住这个算例）**：8 卡，梯度 1 GB，IB 400 Gb/s（B = 50 GB/s）

```
带宽项 = 1.75 GB / 50 GB/s = 35 ms
延迟项 = 14 × 1.5 µs ≈ 21 µs   ← 可忽略
⇒ 约 35 ms
```

### 1.5 小消息为什么换成 tree

S 很小（< 百 KB）时，`2(N−1)·α` 主导。tree 的**深度**是 log N 而不是 N−1：

```
ring:  2(N−1) 步 × α          N=8 → 14α ≈ 21 µs
tree:  2·log2(N) 步 × α       N=8 → 6α  ≈ 9 µs
```

NCCL 会根据消息大小/拓扑自动选 ring 或 tree（`NCCL_ALGO` 可强制）。**这就是"大消息看带宽、小消息看延迟"的物理来源。**

## 2. TP / PP / DP / EP：四种并行切的是什么

| | 切什么 | 通信模式 | 通信量级 | 瓶颈 | 典型规模 |
|---|---|---|---|---|---|
| **DP** 数据并行 | 切 batch | 梯度 allreduce（每步一次） | ∝ **参数量** | 参数量大就要 ZeRO 分片 | 几十~上千卡 |
| **TP** 张量并行 | 切权重矩阵的行/列 | 每层 **2 次 allreduce**（前向）+ 2 次（反向） | ∝ **激活 × 层数** | **带宽**，必须 NVLink | ≤ 8（节点内） |
| **PP** 流水并行 | 切层 | 段间点对点 send/recv | ∝ 激活 × 1 | **bubble（空泡）** | 跨节点，几十段 |
| **EP** 专家并行 | 切 MoE 专家 | all-to-all | ∝ 激活 × top-k | 带宽 + 负载不均 | MoE 专用 |

### 2.1 TP：为什么"每层两次 allreduce"

Megatron 的切法（一个 Transformer 层内）：

```
Attention:  QKV 按列切（各卡算一部分 head）→ 输出 o_proj 按行切 → allreduce ①
MLP:        up/gate 按列切 → down 按行切 → allreduce ②
```

**前向 2 次，反向 2 次，每层都发生。** 所以 TP 的通信量随**层数线性增长**，这也是它只能待在 NVLink 域内的原因：

| 链路 | 单向带宽 | 倍数 |
|---|---|---|
| H100 NVLink | ≈ 450 GB/s | 9× |
| IB 400 Gb/s (NDR) | 50 GB/s | 1× |

**一句话结论：TP 靠带宽堆，PP 靠调度藏，DP 靠分片省。**

### 2.2 PP：bubble 公式（能背就背）

切 P 段、喂 M 个 micro-batch（1F1B 调度）：

$$\text{空泡比例} \approx \frac{P-1}{M + P - 1}$$

```
P=8, M=32 → 7/39 ≈ 18%
P=8, M=8  → 7/15 ≈ 47%   ← micro-batch 太少，一半时间在等
```

所以 PP 的调参主线是**让 M 远大于 P**，代价是显存（每个 micro-batch 都要存激活）和 optimizer 的 step 数。

### 2.3 DP：为什么大模型必须 ZeRO

DP 每步 allreduce **全部梯度**。7B 模型 fp16 梯度 = 14 GB：

```
8 卡 ring: 1.75 × 14 GB = 24.5 GB / 卡 / 步
IB 400Gb/s: 24.5 / 50 = 490 ms  ← 一步就半秒
```

ZeRO-1/2/3 分别把 optimizer state / 梯度 / 参数切片，把"每卡都存全量"变成"每卡存 1/N"，通信量随之下降到接近 ring 的下界。

## 3. 面试三问（附可直接说的答案）

### Q1：为什么 ring allreduce 是带宽最优的？

> “因为它把 allreduce 拆成 reduce-scatter + all-gather 两轮，每轮每卡只发 (N−1)/N × S，两轮合计 2(N−1)/N × S。而 allreduce 的数据下界是 2S（每个字节要读一次写一次），N 越大系数越接近 2，所以它贴着下界跑。朴素的『收集-求和-广播』在瓶颈卡上是 2(N−1)S，N=8 就差 8 倍。”

### Q2：8 卡、1 GB 梯度、IB 400 Gb/s，allreduce 至少多久？

> “带宽项 = 2×7/8 × 1 GB = 1.75 GB，除以 50 GB/s 是 35 ms；延迟项 14 步 × 约 1.5 µs ≈ 21 µs，可忽略。所以约 35 ms。如果换 NVLink，单向 450 GB/s，就降到约 3.9 ms。”

### Q3：TP 和 PP，哪个更吃带宽？

> “TP。TP 每层要做两次 allreduce，通信量正比于『激活大小 × 层数』，所以只能在 NVLink 域内、并行度一般不超过 8。PP 只在段间传激活、一次一份，通信量小得多，但它有 bubble，空泡比例约 (P−1)/(M+P−1)，靠堆 micro-batch 摊薄。实际大模型是 3D 并行：节点内 TP、节点间 PP、外面再套 DP。”

## 4. 接到我自己的项目上（这段最重要）

我没有集群，所以**不能声称做过分布式**。但我做过的东西和它有结构上的同构，这是可以讲的：

| 我做过的 | 分布式里的对应物 | 同构点 |
|---|---|---|
| softmax 两级归约（warp shuffle → shared → block） | reduce-scatter → all-gather | 都是"先局部归约、再跨层级交换"，且**层数越多、每层搬的越少** |
| PagedAttention 按 head 切分 | TP 按 head 切 KV cache | attention 本身**不需要通信**，通信只发生在 o_proj 之后 |
| 我算的 AI（算术强度）判瓶颈 | 算通信量判并行策略 | 同一套方法论：先算搬多少字节，再看带宽够不够 |

**如果问"你怎么把 PagedAttention 扩展到多卡"，标准答法**：

> “KV cache 按 head 切：每个 rank 持 H/TP 个 head 的 KV，block table 各自维护。因为 attention 在每个 head 上是独立的，这一步零通信；真正要 allreduce 的是 o_proj 的输出。所以 TP 对 attention 是友好的——切 head 几乎白送。反过来说，如果按序列切（context parallel），就要处理跨卡的 KV 可见性，代价高得多。”
