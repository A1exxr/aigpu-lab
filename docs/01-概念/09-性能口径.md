# 性能口径：P1 与 P2

## 0. 这份文档解决什么问题

同一个 kernel 会出现两个差很远的数字，原因通常不是"测错了"，而是**测的条件不同**：

- 换了一次二进制（重新编译、改了 num_stages、换了 block 大小）；
- 换了一次基准（PyTorch fp32 vs cuBLAS fp16 vs 理论峰值）；
- 换了一次运行（别的程序在跑、GPU 降频、L2 没冲刷）。

不区分这两类数字，就会出现"这个数到底算不算数"的争论。所以先定义。

---

## 0.5 开工前六问（任何对比之前先答完，答不出就不许比）

1. **同一二进制？** 两个数是不是同一次编译产物？（改过 num_stages / block / tile 就是两个二进制）
2. **同一精度？** fp16 对 fp16，fp32 对 fp32。fp16+Tensor Core 对 fp32+CUDA core 是**四倍算力差**，不能比。
3. **同一输入？** 同 shape、同 dtype、同 seed。
4. **同一计时？** 同一 event、交替跑、min-of-N（N≥5）、两次重复差 <2%。
5. **基准是什么？** cuBLAS fp16 / PyTorch fp32 / 峰值 —— 写清楚，不许含糊说"PyTorch"。
6. **分母是什么？** 272 GB/s（标称）、221 GB/s（实测）、65.2 TFLOPS（fp16 峰值）、26.47 TFLOPS（cuBLAS fp16）。

六问里有任何一个答"不确定"，这个数就只能当 P2（自己看），不能进 README / 简历 / 面试口述。

## 1. 两类数字

| | **P1：本轮实测** | **P2：历史记录** |
|---|---|---|
| 来源 | 同一次运行、同一二进制、同一基准，交替计时 | 另一次运行 / 另一版本 / 另一基准 |
| 要求 | min-of-N（N≥5），两次重复误差 <2% | 无害但不能拿来比较 |
| 能否进简历 / README 对比 | **可以** | **不可以** |
| 能否讲"快了多少倍" | 可以 | 不可以（除非注明不同二进制） |

**判定方法**：问一句"这两个数是在同一个进程里、用同一个 event、交替测出来的吗？"——不是，就是 P2。

## 2. GEMM 的例子：99% 是怎么变成 83% 的

### 旧说法（P2 混用，错误）

```
我们的台阶4（wmma）      0.2836 ms   7.57 TFLOPS
PyTorch fp32 基线        0.2889 ms   7.43 TFLOPS
→ "超 PyTorch fp32 基线 1.13×"
```

问题：我们的 kernel 是 **fp16 + Tensor Core**，PyTorch 基线是 **fp32 + CUDA core**（峰值 16.3 vs 65.2 TFLOPS，差 4 倍）。用 tensor core 去打 fp32，赢了不说明实现好，只说明用了更快的硬件单元。

### 新口径（P1，同一二进制内交替计时）

```
cuBLAS fp16（Tensor Core）  0.0834 ms   25.76 TFLOPS   100%
我们的台阶6（64×64 tile）    0.1010 ms   21.27 TFLOPS    83%
我们的台阶5b（cp.async）     0.1763 ms   12.18 TFLOPS    47%
```

三条都是同一进程、同一 event、同输入、交替跑出来的，所以：

- 台阶6 相对 cuBLAS fp16 = **1.21×**（我们慢 1.21 倍，或者说达到 83%）；
- 台阶6 相对台阶5b = **1.75×**（内部加速，这个可以讲）；
- 台阶1→台阶6 = 2.42 → 0.101 = **24.0×**（内部台阶，这个也可以讲）。

### 结论

- 简历 / README 里**只写 P1**：`2.42 → 0.101 ms（24.0×），达同进程 cuBLAS fp16 的 83%`；
- **删掉**"超 PyTorch fp32 1.13×"这类跨口径数；
- 讲"还差 1.21 倍"是加分项（说明知道差距在哪：smem 复用率 + 无 swizzle）。

---

## 3. 三条规则

**R1：只引用 P1。**
写进简历、README、面试口述的数，必须是同一二进制、交替计时、min-of-N 得到的。

**R2：跨二进制的数不进简历。**
"上次 0.28，这次 0.12"可以说，但要注明"换了 64×64 tile"；不能写成"快了 2.3 倍"而不说改了什么。

**R3：分母必须写清楚。**
- 带宽百分比：分母是 **272 GB/s（标称）** 还是 **221 GB/s（实测天花板）**，要写；
- TFLOPS 百分比：分母是 **65.2（fp16 TC 峰值）**；
- 相对加速：分母是 **cuBLAS fp16** 还是 **PyTorch fp32**，要写。

## 5. 禁止的表述（说过就改）

- ❌ "超 PyTorch 1.13×"（跨精度、跨基准）
- ❌ "达到 cuBLAS 的 99%"（不同二进制 / 不同测法）
- ❌ "快了 2.33 倍" 而不说和谁比
- ❌ "带宽 212%"（公式套错，是 flash 的 4SD 而非 4SD+4S²）
- ❌ "已到墙"（除非 ncu DRAM 吞吐 >90% 且 occupancy 正常）
